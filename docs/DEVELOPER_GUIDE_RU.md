# Tg2max: Полная Документация По Коду (Для Новичков)

Этот документ объясняет, как устроен проект `telegram2max`, начиная с базовых идей и заканчивая деталями всех ключевых подсистем.

Цель: после прочтения вы должны уметь:
1. Понимать, что делает каждая часть программы.
2. Объяснить другому человеку, как бот работает «под капотом».
3. Безопасно вносить изменения в код.
4. Находить и диагностировать ошибки в проде.

---

## 1. Что Это За Проект

`Tg2max` — это Telegram-бот-мост между Telegram и MAX.

Что умеет бот:
1. Авторизация пользователя в MAX (токен или QR).
2. Показ списка чатов MAX.
3. Показ истории чата MAX внутри Telegram.
4. Отправка текста/медиа из Telegram в MAX.
5. Получение обновлений MAX и уведомления в Telegram.
6. Автообновление открытого чата.
7. Очередь исходящих сообщений, если MAX временно недоступен.
8. Техкоманды `/health` и `/stats`.

---

## 2. Главная Идея Архитектуры

Архитектура простая, но многослойная:
1. `bot.py` — Telegram-слой (UI, FSM, callback-обработчики, фоновая логика, рендер).
2. `max_manager.py` — слой MAX-сессий + хранилище пользователей/токенов/очереди.
3. `sessions/users.db` — SQLite база данных.
4. Папка `sessions/` — runtime-данные, временные файлы, MAX-сессии, кэши.

Практически все Telegram-обработчики в `bot.py` используют `session_manager` (экземпляр `MaxSessionManager`) как единую точку работы с MAX.

---

## 3. Файлы Проекта И Их Роль

1. `bot.py`
Крупный orchestration-файл: UI, бизнес-логика, фоновые циклы, FSM, рендер историй, отправка/получение медиа, обработчики команд и callback.

2. `max_manager.py`
Изолирует MAX API и персистентность:
- безопасное хранение токена,
- создание/переиспользование клиента MAX,
- QR-авторизация,
- logout,
- очередь исходящих сообщений.

3. `Dockerfile`, `docker-compose.yml`
Запуск проекта в контейнере.

4. `main.png`, `chats.png`, `instruction.png`
Картинки для экранов меню и инструкции.

5. `sessions/`
Runtime-папка:
- `users.db` (SQLite),
- `outbox/` (вложения очереди),
- `tmp_media/` (временные скачанные файлы),
- `ui_photo_file_ids.json` (кэш file_id картинок UI),
- сессионные папки MAX (`user_<id>`, `user_<id>_auth`).

4. `requests`
Скачивание файлов по URL в fallback-сценариях.

5. `sqlite3`
Локальная БД для пользователей и очереди.

## 5. Конфигурация Через ENV

Обязательные переменные:
1. `BOT_TOKEN` — токен Telegram-бота.
2. `TOKEN_ENCRYPTION_KEY` — ключ Fernet для шифрования токенов MAX.

Необязательные:
1. `BOT_USERNAME` — username бота без `@` (нужен для deep-link ссылок).
2. `ADMIN_IDS` — id админов для `/health` и `/stats`.
3. `UPDATE_POLL_SECONDS` — частота опроса обновлений MAX.
4. `CHAT_AUTORELOAD_SECONDS` — автообновление открытого чата.
5. `QUEUE_RETRY_SECONDS` — интервал ретраев очереди.
6. `QUEUE_BATCH_SIZE` — размер пачки сообщений очереди за цикл.

## 6. Жизненный Цикл Программы

Точка входа: `main()` в `bot.py`.

Порядок запуска:
1. Создаются runtime-директории.
2. Загружается кэш file_id UI-картинок.
3. Опционально определяется `BOT_USERNAME` через `get_me`.
4. Поднимаются 3 фоновые задачи:
- `updates_loop()`
- `chat_refresh_loop()`
- `outgoing_queue_loop()`
5. Стартует polling Telegram (`dp.start_polling(bot)`).

При остановке:
1. Отмена фоновых задач.
2. `session_manager.shutdown()` (закрытие MAX-клиентов).
3. Закрытие Telegram-сессии.

## 7. Хранение Данных: Что Где Лежит

### 7.1 SQLite: таблица `users`
Поля:
1. `tg_user_id` — PK.
2. `username`, `first_name`, `last_name`.
3. `max_token` — шифрованный токен (`enc:v1:...`).
4. `created_at`, `updated_at`.

### 7.2 SQLite: таблица `outgoing_queue`
Поля:
1. `id` — PK AUTOINCREMENT.
2. `tg_user_id`, `chat_id`, `text`.
3. `attachment_type`, `attachment_path`, `attachment_name`.
4. `attempt_count`, `last_error`.
5. `created_at`, `updated_at`.

Назначение: не терять исходящие сообщения, если MAX временно недоступен.

### 7.3 In-memory структуры в `bot.py`
1. `CHAT_CACHE` — кэш списка чатов пользователя.
2. `MEDIA_CACHE` + `MEDIA_REQUEST_INDEX` — кэш ссылок `/media_xxx`.
3. `HISTORY_ANCHORS` — «якорь времени» для пагинации истории.
4. `UPDATE_LAST_SEEN` — последняя «прочитанная метка времени» для уведомлений.
5. `UNREAD_COUNTS` — счетчик непрочитанных по чатам.
6. `ACTIVE_CHAT_VIEWS` — какой чат сейчас открыт у пользователя в Telegram.
7. `METRICS` — runtime-метрики `/health` и `/stats`.

Важно: это RAM, после рестарта очищается.

## 8. Безопасность Токенов: Как Это Реально Работает

Реализовано в `UserStore` (`max_manager.py`).

Процесс:
1. На старте читается `TOKEN_ENCRYPTION_KEY`.
2. Создается `Fernet` объект.
3. При `set_token(...)` токен шифруется и сохраняется как `enc:v1:<ciphertext>`.
4. При `get_token(...)`:
- если токен с префиксом `enc:v1:` — расшифровка,
- если без префикса — legacy plaintext, бот мигрирует его в шифрованный вид.
5. На старте бота `_migrate_plaintext_tokens()` массово мигрирует старые токены.

Что это защищает:
1. Утечка БД без ключа не позволяет прочитать токены.
2. Смена ключа ломает расшифровку старых токенов (это важно учитывать).

## 9. Модуль `max_manager.py` По Частям

## 9.1 `UserStore`
Ответственность: SQLite + шифрование токенов + очередь.

Ключевые методы:
1. `_init_schema()` — создает таблицы/индекс.
2. `register_user(...)` — upsert Telegram-пользователя.
3. `get_token(...)` / `set_token(...)` / `clear_token(...)`.
4. `enqueue_outgoing(...)` / `fetch_outgoing(...)` / `mark_outgoing_*`.

## 9.2 `MaxSessionManager`
Ответственность: MAX-клиенты и auth-flow.

Главные идеи:
1. Один lock на каждого пользователя (`_locks`), чтобы не было гонок при connect/disconnect.
2. `_contexts` хранит активные MAX-клиенты.
3. `_auth_contexts` хранит временные данные QR-авторизации.

Ключевые методы:
1. `ensure_client(tg_user_id)`
- берет токен из store,
- создает/переиспользует `MaxClient`,
- делает connect/sync/post-login.

2. `validate_and_save_token(...)`
- временно сохраняет новый токен,
- пробует подключиться и запросить чаты,
- если неудача — откат к старому токену.

3. `begin_qr_login(...)`
- запускает auth-клиент,
- запрашивает `trackId`, `qrLink`, `expiresAt`.

4. `check_qr_login(...)`
- проверяет статус QR,
- по готовности извлекает login token,
- возвращает `pending | expired | ready`.

5. `logout(...)`
- logout в MAX,
- очистка auth-контекста,
- удаление токена,
- сброс session-кэшей.

## 10. Модуль `bot.py` По Подсистемам

## 10.1 FSM
Состояния:
1. `waiting_for_token` — ожидаем токен от пользователя.
2. `waiting_for_chat_message` — ожидаем контент для отправки в конкретный чат.

## 10.2 Экранная модель UI

Ключевой helper: `switch_screen_message(...)`.

Правило:
1. Фото -> Фото: пытаемся edit media/caption.
2. Текст -> Текст: edit text.
3. Фото -> Текст или Текст -> Фото: delete + send new.

Это решает ограничения Telegram API и сохраняет «чистый» UX.

## 10.3 Кэш file_id UI-картинок

Проблема: отправка фото по файлу может быть медленной.
Решение:
1. После первой отправки берется Telegram `file_id`.
2. Этот `file_id` сохраняется в `sessions/ui_photo_file_ids.json`.
3. Следующие отправки идут по `file_id` (значительно быстрее).
4. Если файл картинки поменялся (SHA1 другой) — кэш инвалидируется.

## 10.4 Нормализация токена (`normalize_token_input`)

Поддерживается:
1. Чистый токен `An_...`.
2. `Bearer ...`.
3. JSON `{"token":"...","viewerId":...}`.
4. JS-like map через `ast.literal_eval`.
5. Фрагменты `token=...`, `auth_token:...` и т.д.

Цель: принять максимум пользовательских форматов без ручной правки.

## 10.5 Построение списка чатов

`get_chat_entries(...)`:
1. Берет данные из `client.dialogs`, `client.chats`, `client.channels`.
2. Пытается сделать `fetch_chats()` для актуализации.
3. Для DIALOG без title подгружает имя второго участника через `get_users()`.
4. Сортирует по `last_event_time` по убыванию.
5. Кэширует в `CHAT_CACHE` на `CHAT_CACHE_TTL_SECONDS`.

## 10.6 Построение истории чата

`build_history_text(...)`:
1. Берет якорь времени из `HISTORY_ANCHORS`.
2. Загружает историю `fetch_history(..., backward=...)`.
3. Дедуплицирует сообщения по `msg.id`.
4. Сортирует по времени.
5. Делает пагинацию через `offset`.
6. Рендерит sender + text + вложения + link/forward-контекст.
7. Оборачивает каждый блок в `<blockquote expandable>`.
8. Режет ответ по лимиту Telegram, но оставляет «самое новое».
9. Формирует клавиатуру навигации/паузы/действий.

Дополнительно:
1. На своих сообщениях добавляет `🗑️` deep-link удаления.
2. Если чат открыт на offset=0, учитывает состояние паузы автообновления.

## 10.7 Медиа из MAX в Telegram

Механизм:
1. В истории у вложений дается ссылка `/start media_<token>`.
2. Токен резолвится через `MEDIA_CACHE`.
3. Бот достает URL/ID через MAX API.
4. Пытается отправить по URL.
5. Если Telegram не может скачать URL напрямую, бот сам скачивает файл во временную папку и отправляет `FSInputFile`.
6. Для каждого выданного медиа есть кнопка закрытия уведомления.

## 10.8 Удаление сообщений из MAX

Сценарий:
1. В истории у своих сообщений ссылка `🗑️` вида `/start del_<chat_id>_<message_id>`.
2. `/start` парсит payload и вызывает `delete_max_message_by_link(...)`.
3. Используется `client.delete_message(chat_id, [message_id], for_me=False)`.
4. Показ `Сообщение удалено!` и автоудаление этого service-message.
5. Принудительный refresh активного чата (с несколькими попытками).

## 10.9 Очередь исходящих

Если direct send в MAX упал временно:
1. Сообщение (и вложение) сохраняются в SQLite + файл в `sessions/outbox`.
2. Пользователь получает уведомление «добавлено в очередь».
3. Фоновый `outgoing_queue_loop()` периодически отправляет очередь.
4. После успеха запись удаляется, временный файл очищается.

## 10.10 Уведомления о входящих

`updates_loop()` -> `poll_updates_for_user(...)`:
1. Периодически проверяет последние события в чатах.
2. Находит сообщения новее `UPDATE_LAST_SEEN`.
3. Не уведомляет о собственных сообщениях.
4. Если чат открыт и не на паузе — не спамит уведомлениями, а просто считает прочитанным.
5. Иначе отправляет уведомление с кнопками:
- `✅ Прочитать`
- `💬 Перейти в чат`

6. `/stats`
Счетчики отправок/ошибок/latency (admin-only, если задан `ADMIN_IDS`).

## 13. Как Работает Автообновление Чата

Механизм:
1. Когда пользователь открывает чат на `offset=0`, в `ACTIVE_CHAT_VIEWS` сохраняется его вид.
2. `chat_refresh_loop()` каждые `CHAT_AUTORELOAD_SECONDS` вызывает refresh.
3. Если подпись `chat_view_signature` не изменилась, сообщение не редактируется.
4. Кнопка `⏸ Пауза` переключает `paused=True`.
5. `▶️ Продолжить` возвращает автоподгрузку.

Плюс: ручной `refresh_active_chat_view_now(...)` используется в особых сценариях (например после удаления сообщения).

## 15. Типовые Сценарии (Пошагово)

### 15.1 Новый пользователь: вход по токену
1. `/start` -> кнопка «Войти в MAX».
2. `auth:token` -> состояние `waiting_for_token`.
3. Пользователь шлет токен/JSON.
4. `normalize_token_input` извлекает токен.
5. `validate_and_save_token` проверяет его через MAX.
6. При успехе показывается главное меню.

### 15.2 Вход по QR
1. `auth:qr` -> `begin_qr_login`.
2. Пользователь сканирует QR в MAX.
3. `auth:qr:check` -> `check_qr_login`.
4. При `ready` токен сохраняется, пользователь авторизован.

### 15.3 Отправка сообщения в чат
1. Открыть чат -> `write:<chat_id>:<chat_page>`.
2. FSM `waiting_for_chat_message`.
3. Пользователь шлет текст/медиа.
4. Бот удаляет пользовательское Telegram-сообщение.
5. Пытается отправить в MAX.
6. При успехе перерисовывает историю.
7. При временной ошибке — ставит в очередь.

### 15.4 Получение входящего сообщения из MAX
1. `updates_loop` замечает новые события.
2. Если чат не открыт в live-view, отправляется Telegram-уведомление.
3. Пользователь может:
- `Прочитать` (закрыть и погасить unread),
- `Перейти в чат` (сразу открыть историю).

## 16. Частые Проблемы И Причины

1. `TelegramConflictError: terminated by other getUpdates request`
Причина: одновременно запущено больше одного процесса бота с тем же токеном.
Решение: оставить ровно один активный инстанс.

2. «Фото экраны отправляются медленно»
Причина: нет кэша file_id или изменились файлы картинок.
Решение: дать боту 1-2 успешные отправки; проверить `sessions/ui_photo_file_ids.json`.

3. «Сообщения иногда уходят в очередь»
Причина: сетевые/временные ошибки MAX.
Решение: это штатное поведение; очередь сама дожмет доставку.

4. «Не могу зайти по QR»
Причина: QR истек, сеть, 2FA challenge.
Решение: обновить QR, проверить сеть; при 2FA использовать вход по токену.

## 17. Где И Как Безопасно Менять Код

Если хотите расширять проект, начинайте с этих точек:
1. Новые кнопки/экраны: функции клавиатур + соответствующий callback.
2. Новый текст UI: функции `*_text()`.
3. Логика уведомлений: `poll_updates_for_user`.
4. Логика рендера истории: `build_history_text`.
5. Работа с MAX API: `MaxSessionManager`.
6. Очередь отправки: `flush_outgoing_for_user`.

Правило безопасной правки:
1. После правок запускать `python -m py_compile bot.py max_manager.py`.
2. Если запуск в Docker, делать `docker compose build` и `docker compose up -d --force-recreate`.
3. Проверять `docker compose logs --tail=120 max_bridge_bot`.

## 18. Как Объяснить Этот Код Другому Человеку (Короткий Скрипт)

Можно объяснить так:
1. «Есть Telegram-слой и MAX-слой».

Если человек понял эти 6 пунктов, он уже понимает основу всей программы.
